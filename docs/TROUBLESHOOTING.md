# 排障与恢复

先双击 `Status.bat`，再打开管理页面查看服务版本、接入状态、CC Switch 连接与当前供应商设置。问题反馈无需提供 API Key；不要直接上传 `.runtime/`、CC Switch 数据库、Codex 配置或历史会话。

## 启动失败或浏览器打不开

| 现象 | 检查与处理 |
| --- | --- |
| ZIP 内双击启动无效 | 先完整解压，放在当前用户可写的目录，再运行 `Start.bat` |
| Node.js 下载失败 | 确认可以访问 `https://nodejs.org/`，再重试；也可自行安装官方 Node.js 24+。不要换成来历不明的运行时或跳过校验 |
| SHA-256 不一致 | 停止使用该下载，删除失败的下载临时文件后重试；持续失败时报告版本与错误，不要执行校验失败的程序 |
| 18181 端口被占用 | 确认是否已运行另一份本工具，先停止旧副本；若是其他软件，请使用自定义端口，不要强杀未知进程 |
| 页面打开但版本未更新 | 停止同一目录的旧服务，再启动并刷新页面；检查桌面快捷方式是否指向旧目录 |
| 页面提示凭据失效/需要重新连接 | 点击「重新连接管理页」。服务重启会使旧页面令牌失效，尚未保存的修改需重新确认，不能直接重放旧写入 |

端口或配置路径改动应先停服务；命令行示例见 [README](../README.md#开发与命令行)。自定义运行目录时，`start`、`status`、`stop` 必须使用同一个 `--runtime`。

## 已启动，Codex 仍然没有经过过滤

1. 在 CC Switch 开启本地代理与 Codex 接管。
2. 检查 `Status.bat`：`ccSwitchReachable` 应为 `true`，`state` 应为 `filtering`。
3. 完全退出并重开 Codex。正在运行的窗口可能缓存接入前的地址。
4. 发送一个正常请求，观察页面转发/过滤计数是否变化。历史总计数可能来自旧请求，不能仅凭“非零”认定当前窗口已接入。
5. 核对供应商的「历史过滤」是否开启。`state=filtering` 只表示地址已接入；模型保护与历史过滤仍分别按设置执行。

本工具只接管顶层 `model_provider` 指定的常规 `[model_providers.NAME]` 单行 `base_url`。如果使用 `--profile`、命令行 `--config`、其他 `CODEX_HOME` 或应用内独立配置，请确认客户端实际读取的文件。复杂多行 TOML 可能无法安全识别。

| 状态 | 含义 |
| --- | --- |
| `filtering` | 当前配置地址已接入过滤层，不保证每个窗口已读取或每项功能都开启 |
| `waiting-for-ccswitch` | 当前配置尚未指向可接管的 CC Switch 地址；工具待命，不强行覆盖外部直连地址 |
| `waiting-for-supported-provider` | 找不到可识别的 provider / base_url 配置 |
| `config-error` | 配置接入失败，查看 `lastError` |
| `stale-state` | 运行记录仍在，但进程已不存在；正常重新启动或停止即可清理 |
| `unresponsive` | 记录的进程仍存在但管理接口不响应；先核对进程归属，不要删恢复数据或随意结束其他程序 |

## 旧会话仍提示加密内容无法解密

历史过滤适用于仍含可读消息和工具结果的记录。确认目标供应商已开启历史过滤，并且请求计数及清理计数随新的请求增加。

它不会解密密文，而是移除不适合跨账号/上游复用的内部 reasoning 与部分历史 ID。原会话若只剩加密的压缩摘要、`previous_response_id`、`item_reference` 或其他服务器引用，工具不能重建未提供的明文，会明确拒绝而非静默丢弃历史。请在仍可访问原会话时生成明文任务摘要，创建新会话继续。

`include: reasoning.encrypted_content` 请求的是**新响应**附带的密文，不等于旧历史密文。有些供应商要求保留此选项；如果开启历史过滤后遇到请求参数 400，可在该供应商「配置」中检查「保留新响应加密内容请求」。这不会取消对旧历史的清理。

## 检测失败、锁定或回答迟迟不显示

- **未能验证**：可能是超时、余额/额度、限流、认证、样本不足、参考库缺失或统计结果模糊，不代表已确认模型降智。查看「检测记录 → 查看说明」。
- **模型不受支持**：当前参考库未收录该模型，不能靠相似名称绕过验证。可关闭该供应商保护继续正常使用，历史过滤不受影响。
- **模型名不一致**：检查供应商是否返回别名。严格检查可能因此锁定；不要把它直接当作供应商欺诈证据。
- **已锁定**：切回该供应商后手动复测，或清除对应锁定，再由下一次受保护请求重新验证。清除锁定不等于通过。
- **等待整段输出**：保护需要完整响应验证后再交付，期间没有逐 token 内容或工具调用；检测和长回复都会增加等待时间。
- **提示路由无法固定验证**：关闭 CC Switch 自动故障转移，确认只有一个当前供应商且地址有效，避免请求中途切换。
- **手动检测 401 / 客户端不受支持**：先让 Codex 经本工具发出一次正常请求再试；部分供应商限定客户端，手动探针可能无法兼容。

默认情况下，空闲时不会按间隔主动检测。间隔表示通过结果的复用时间，详见 [模型保护](../MODEL-GUARD.md)。

## 长会话自动压缩失败、WebSocket 错误

历史过滤或模型保护生效时，`/responses/compact` 与不可移植的加密压缩历史会被拒绝；请提前整理明文摘要后新建会话。关闭相应功能可恢复其原有转发路径，但不能解决上游自身的密文不兼容。

本工具只支持 Responses HTTP/SSE。WebSocket 握手返回 426；若客户端启用了 WebSocket 传输，请改为 HTTP/SSE。其他接口及新协议没有全面兼容保证。

## 重启、搬迁、卸载与异常恢复

电脑重启后，Codex 配置可能仍指向本机过滤地址。先双击桌面入口恢复监听，或从原目录运行 `Stop.bat` 恢复地址，然后再打开 Codex。

移动或卸载项目之前先停止。停止时，只恢复工具写入且尚未被其他程序替换的精确 `base_url`，不会还原整份旧配置。**恢复完成前不要删除 `.runtime/routes.json`。** 如已意外丢失该文件，可在 CC Switch 重新执行 Codex 接管，再完全重启 Codex；恢复后再决定是否重新接入过滤。

若 `.runtime/model-guard.json` 损坏，服务会暂停放行，避免锁定丢失后误放行。先停止服务，备份损坏文件，检查并恢复自己的 `.runtime/model-guard.json.previous`，再启动。不要下载或复制其他人的运行文件。

## 反馈问题时提供什么

请提供：Windows/架构、发布版本与页面服务版本、CC Switch 版本、Codex 版本、重现步骤、是否开启历史过滤/模型保护/自动 failover、错误码与时间。尽量用虚构供应商和无项目内容的最小案例。

只截取必要的错误文本。提交前移除 API Key、管理令牌、认证头、私人域名/查询参数、供应商 ID、个人路径、项目内容及会话数据。检测记录可能包含真实供应商名称，截图也需检查。涉及安全问题请按照 [SECURITY.md](../SECURITY.md) 私下报告。
