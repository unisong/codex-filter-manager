# 更新记录

最新版本可从 [GitHub Releases](https://github.com/unisong/codex-filter-manager/releases/latest) 获取；旧发布包和标签已撤回，这里保留各阶段的功能改动记录。服务版本号单独记录在 `src/proxy.cjs`，产品版本号来自根目录 `package.json`。

## 未发布

- 修复完整工作台通过 Magpie 路由组或 fallback 发送的请求未经历史过滤：请求名称是分组而不是供应商，路由前的前缀规则不会命中，旧会话发往已开启过滤的供应商时仍会报加密内容或跨资源错误。现在每次实际尝试某个供应商时，按该供应商的规则过滤；直接选择供应商的请求不变，也不会重复过滤。这一步无法拒绝请求，无法安全迁移的服务器引用只能原样发送。
- 完整工作台的 DeepSeek Schema 折叠只做放宽：联合类型中有无法解析的 `$ref` 或形状未知的分支时，根 `required` 不再取已知分支的交集，避免让模型漏填原本可省略的字段。Codex 实际的 `automation_update` 折叠结果不变，并补充非 DeepSeek 候选逐字节不变的测试。
- 社区纯过滤插件保持 v0.1.1；相关文档不再提及已撤回的 v0.1.2。

## v1.0.18 / 服务 v40

- **DeepSeek Schema** 统一为逐供应商显式开启的 DeepSeek 协议转码兼容，任何供应商 ID 都不再默认开启或特殊处理。已在规则中写入 `"deepSeekObjectRoot": true` 的配置不受影响；此前依赖隐式默认的供应商，需要在原生设置页或工作台为其打开该开关。
- 修复开关顺序影响默认值：先开启 DeepSeek Schema、再开启历史过滤的供应商，同样默认保留新响应密文请求；已保存的取值保持不变。
- 公开源码、测试与文档不再出现真实供应商名称或域名，测试统一使用虚构数据；第三方说明仅为许可署名保留上游仓库地址。`release:check` 可读取本机不提交的词表，扫描暂存文件、提交说明与发布说明。
- 发布包改为只从已提交的 HEAD 生成，不再读取工作区文件，避免把 Magpie 写入的本机暂停规则或探针凭据打包。
- 稳定 Windows 冷启动下的 PID 复用测试：先预热 PowerShell，避免首次进程查询超时后被保守判定为“仍在运行”。

## v1.0.10 / 服务 v35

- 修复 CC Switch 数据库短暂锁定时，规则读取失败被误当成“关闭过滤”而原样转发，造成旧会话间歇出现跨资源 400 的问题。锁冲突最多异步重试 3 次；仍无法读取时返回带本地请求编号的 503，不向上游发送未确认规则的请求。
- 上传完成后的二次规则检查使用相同保护；重试期间重新读取当前供应商，不复用旧供应商规则。原有主动关闭、未配置供应商与自动故障转移的行为保持不变。
- 诊断保留脱敏后的 SQLite 错误类别、规则读取重试与拒绝记录；管理页在恢复后仍保留本次运行的异常提示，支持直接打开诊断。
- 修复检查更新时向 GitHub 版本查询接口发送二进制下载标头而返回 HTTP 415；版本查询使用 JSON，发布附件继续使用二进制下载。
- 两套工作台右上角增加关闭按钮，确认后停止本工具对应服务；CC Switch 恢复 Codex 配置，Magpie 保留宿主及历史过滤。
- 设置页增加手动检查更新与版本选择。Windows 发布包支持校验下载、备份安装、自动重启及失败恢复；Magpie 支持下载并准备独立新版插件目录。
- 服务关闭时取消正在进行的检测，不改变评分、历史过滤、保护开关或已保存的锁定。
- 增加关闭与更新 API 的授权检查、安装失败恢复及两套页面的离线浏览器测试。
