# 模型一致性保护

**模式差异：** 以下自动放行、锁定和响应缓冲机制适用于 CC Switch 独立代理。本仓库附带的 Magpie 历史钩子配合管理页只支持手动检测；另行分发的 [Magpie 合并工作台](https://github.com/unisong/magpie-codex-history-filter) 有自己的定期观测和异常暂停机制，以其说明为准。

本功能在界面中称为「模型保护」，也常被称为“降智检测”。更准确地说，它检查**数字输出统计指纹是否与参考模型一致**，并在本机响应交付前提供中止机制。它不测试编程能力、推理质量、上下文理解能力或供应商分配的计算预算。

## 算法来源与接入方式

实际采用的开源项目是 **[xqy2006/ModelTrace](https://github.com/xqy2006/ModelTrace)**。本项目包含其 MIT 许可的评分核心与参考库，固定来源为提交 [`6cd4a8ff0f3f4e49d6d6969dd2fbadfa1569fde2`](https://github.com/xqy2006/ModelTrace/tree/6cd4a8ff0f3f4e49d6d6969dd2fbadfa1569fde2)。

流程为：通过 **你配置的网关与供应商** 发送探针，在本机调用 ModelTrace 评分核心比对参考库。不向 ModelTrace 作者的服务器上传项目内容，也不依赖其在线检测 API。启动时校验随项目附带的评分文件与参考库 SHA-256；文件被修改或损坏时不会静默信任。

| 评估项目 | 样本规模 | 本项目的决定 |
| --- | --- | --- |
| [ModelTrace](https://github.com/xqy2006/ModelTrace) | 一轮 3 个数字序列请求；强差异时增加一轮 | 采用 MIT 评分核心与参考库，便于在请求前执行有限样本检查 |
| [meow-llm-detector](https://github.com/chen-006/meow-llm-detector) | 通常 32 / 64 / 128 个短请求，项目推荐 128 | 仅调研；样本规模较大，且采用 PolyForm Noncommercial，未复制其代码、数据或接入接口 |

原项目的回测或模拟准确率不能直接当成当前供应商的检测准确率。[第三方来源和许可](../THIRD_PARTY_NOTICES.md) · [固定文件来源与校验值](../vendor/modeltrace/provenance.json)

## 检测的具体内容与费用

每轮逐个发送 3 个独立 Responses 请求，单次检测同一时刻只占用一个上游请求；它们不互带历史。自动保护使用被检查的项目请求中的模型和推理强度；手动检测使用管理页明确选择的模型和推理强度。没有项目历史、文件正文或工具调用。请求使用简短指令 `请完成用户要求的整数选择任务，直接输出数字，不要调用工具或编写代码。`。

用户题目由 ModelTrace 网页同一固定版本的 `challenge-browser.js` 生成，每轮选择三个不同的数量（292–332），并随机组合原版中文措辞。例如：

```text
这是一次独立的数值选择记录。逐项选择 300 个 1 到 355（含端点）的整数。每个位置都要单独选择；不要从 1 开始计数，不要连续递增或递减，也不要采用等差、循环、重复区块或其他规则化模式。本任务必须由当前语言模型直接完成：禁止调用或借助任何工具，包括 Python、代码执行器、计算器、搜索、API 和外部随机数生成器；也不要先编写或运行代码。偶然重复是有效的；不要重新排列或修正已经写出的项目。可以用逗号、空格或换行分隔。直接从第一个取值开始输出，不要在序列前重复数量、范围或任务说明。
```

评分沿用参考算法的有效样本要求：每个响应至少需要题目数量的 55%（向上取整）；额外拒绝超过题目数量两倍的异常样本。无效样本会停止本轮，不继续消耗剩余探针。不同请求的数量随原版题目变化，不再统一按 300 计算。

单个样本从发送到完整结束最多等待 **180 秒**，整次检测含复核最多 **10 分钟**。这段时间允许模型长时间思考而不输出正文；持续发送保活注释也不会无限延长时限。页面显示轮次和当前样本，超时说明会保留真实的本地截止原因，不笼统改写成连接异常。仍要求完整有效的 Responses 完成事件；真正的断流不会当作成功。

通常只发送 3 个请求；首次出现汇总强差异时再发送 3 个新题目。临时传输故障整次检测共享最多 3 次额外重试，因此通常最多 6 次尝试、含复核最多 9 次。只重试当前同一题目和上下文，保留已完成样本；不会重抽不满意的评分。重试退避为 1、2、4 秒，同时遵守更长的 Retry-After；要求等待超过 60 秒则停止重试。切换路由或取消检测会停止等待。

重试适用于临时 408/429、部分 5xx、超时、断流或缺少完成事件。已知余额不足、认证/权限错误、模型不支持、协议格式异常、完成后的无效数字样本及模型名不符不重试。若服务、认证、样本或整次等待时限提前失败，会在发完全部请求之前结束。每次尝试的输入、输出和隐藏推理 token 均可能计费，不能用数字数量准确推导费用。本工具没有固定的“每次检测 token 用量”，也不在管理界面展示费用估算。

正文以完整结束响应的 output 数组为优先来源，避免空 output_text 字段或空白/片段 delta 遮住完整数字回答。没有完整正文时才回退到 delta；仍必须收到正确模型的完成响应，推理内容不参与评分。

使用同一出题器和评分器不代表请求环境完全相同：Codex 会话还有系统指令、上下文和客户端设置。自动探针始终独立，不复制真实项目内容；供应商也可能对不同请求采用不同路由，因此不能保证每次与手工网页测试结论相同。

## 结果与拦截规则

分数是**当前参考集合内的相对权重，不是模型身份置信度**。当前默认判定为：

| 结果 | 条件与行为 |
| --- | --- |
| 通过 · 样本匹配 | 请求模型汇总排名第一且权重至少 0.5，无单样本强差异或完全重复序列；建立有时限的通过缓存 |
| 明显差异，复核中 | 另一候选权重至少 0.8、请求模型权重至多 0.15、两者差至少 0.65；暂停项目请求并进行第二轮 |
| 锁定 | 第二轮汇总同样达到强差异阈值且指向同一其他模型，复核不复用首轮数字序列；持久锁定对应路由、模型和推理强度 |
| 样本冲突 | 单个样本满足强差异阈值但汇总未达到强差异；不判为通过，不新增持久锁定，撤销相关已放行响应的授权 |
| 模型名不一致 | 探针或项目响应声明的模型不符，立即锁定；这也可能是供应商别名兼容问题，不能单凭模型名证明能力下降 |
| 未能验证 | 超时、限流、无效样本、结果模糊、参考库未收录或协议异常；受保护请求不放行，但不标记为确认降智 |

严格的模型名检查允许请求模型原名，以及在其后追加 `-YYYY-MM-DD` 的日期版本名；其他别名应先确认供应商的接口行为。

每个样本和三份合并样本均使用未修改的 ModelTrace 评分器。单样本按单样本规模评分，不冒充三样本结果。完全相同的序列不能视为独立证据；复核仍最接近同一替代模型但分数较弱时，保留首轮异常并说明未达到持久锁定阈值。

页面颜色与当前是否拦截分别表达：有效通过为绿色；强汇总差异、强单样本冲突、复核中或锁定为红色；403、网络失败、数字无效、重复样本或较弱的不确定结果为黄色。红色不等于已经新增持久锁定。最近结论在保护关闭或缓存到期后仍保留，「自动保护」状态行单独说明当前是否拦截和是否需要重检。

### 与 ModelTrace 原项目判定的区别

ModelTrace 网页主要显示候选排名和相对权重，不负责针对你的目标模型作通过/切断决定。其固定版本 Codex 插件的分类函数也包含 0.5/0.8/0.15/0.65 阈值，但实际触发告警和停止使用的是 `isMismatch`：第一候选与请求模型不同且请求模型权重有效；不要求先达到 0.8。默认追加 3 次确认，每次都与目标模型不同即可，不要求替代候选相同。无效样本、缺失结果和超时不算该统计差异。

本工具采用上表的独立放行规则；不能将其描述为完全复制原插件的拦截策略。原插件在保留冻结上下文的临时 Codex 分支中取样，本工具使用不含项目上下文的独立 HTTP 探针，两者请求环境也不同。[原插件源码](https://github.com/xqy2006/ModelTrace/blob/6cd4a8ff0f3f4e49d6d6969dd2fbadfa1569fde2/codex-plugin/modeltrace-guard/scripts/state.mjs) · [原插件说明](https://github.com/xqy2006/ModelTrace/blob/6cd4a8ff0f3f4e49d6d6969dd2fbadfa1569fde2/codex-plugin/modeltrace-guard/README.md)

每个供应商的保护独立开关，默认关闭。新增供应商不会自动继承其他供应商的保护开关。地址异常时，已有开关仍可关闭；修复后才能重新开启。关闭保护后保留的锁定会标为「保留锁定 · 保护已关闭」，不表示此时仍在执行保护。

锁定可手动清除；清除只允许重新检测。手动复测通过也可解除锁定。重启不会删除锁定，也不会将历史通过记录重新当成有效缓存。

## 检测模型从哪里来

自动保护逐条读取经过过滤代理的 Responses 请求，使用其中的 `model` 与 `reasoning.effort`；没有指定推理强度时保持上游默认。参考库只用于本地评分，不会替项目选择另一种模型。

管理页优先显示当前供应商最近实际请求的模型，其次采用其检测记录，并标明来源和时间；均无记录时，在当前页展开手动选择，用 Codex 配置值预填。配置值不会被当作实际请求。不同会话或任务可能经过同一代理，因此这里不能识别哪一个是前台会话。

手动检测可以选择模型和推理强度。请确认供应商支持该模型；手动选择只影响这次探针，不改变 Codex 配置或自动保护的模型，也不会覆盖最近捕获的项目请求。切换供应商或路由后，应重新核对手动选择。

## 通过有效期与失败冷却

默认通过结果可复用 10 分钟，可选每次请求或 1–60 分钟。

例如设置为 30 分钟：本次检查通过后的 30 分钟内，同一路由、模型与推理强度可复用结果；过期后的下一次受保护请求先检测，再决定是否发送项目请求。**没有请求时不运行定时探针**，所以空闲时不会因间隔设置产生检测费用。

供应商地址、认证配置、模型、推理强度或代理配置变化会改变检测键。服务重启清空通过缓存。即使缓存仍有效，每次受保护项目响应也会检查模型字段与完整性。界面的最近结果、缓存有效性和当前锁定分别展示，历史成功不等于现在已验证。

失败或无法验证后，同一路由、模型和推理强度进入固定 **60 秒冷却**。冷却期间自动请求继续被拦截，复用失败原因，不发起新探针，也不新增历史记录。冷却结束后由下一次受保护请求触发重试，空闲时不主动重试。手动检测可以绕过冷却立即重试；相同检测正在进行时，重复点击仍合并为一次。

冷却到期时间随检测记录保存，重启后保留尚未结束的冷却；这不会建立通过信任。修改保护设置、切换路由或清除锁定会使相关旧冷却失效。指纹库未收录的模型也会合并冷却期间的重复记录，且不会为其发送探针。

上游 `model_not_found` 表示模型或渠道不可用，HTTP 429 表示限流或排队，认证失败、服务异常和超时同样属于未能验证。界面使用固定的错误说明，不展示上游原始响应正文；这些错误不能作为确认降智的证据。

## 响应保护与开销

保护开启时，项目响应先完整缓存在本机，确认存在 `response.completed` 且模型字段一致，再交付 Codex。等待期间只发送 SSE 保活注释，不发送正文或工具调用。

这会让原本逐步显示的流式回答变成整段显示，也会推迟工具执行。压缩响应先解压验证。单响应 16 MiB、并发总缓存 64 MiB；断流、失败事件、重定向、协议异常或缓存超限均停止放行。受保护重定向不会向客户端传递 `Location`。

未开启保护的供应商保留原有转发行为。开启保护并不是项目文件沙箱：它不能撤回已通过其他请求执行的工具、回滚文件或约束绕过此代理的连接。

CC Switch 自动故障转移开启或路由无法唯一识别时，不能用一次探针批准后续未知路由。存在已开启的保护且不能确定当前路由时，本工具拒绝放行。请关闭自动故障转移，并避免在请求进行中切换供应商。

## 检测记录与本机数据

「检测记录」保留最近 100 次检测尝试的最终结果，每页 10 条，在独立区域内滚动。一次检测的多个样本合为一条记录；参考库不支持等检查可能在发送探针前就结束。通过缓存命中、失败冷却命中、轮询、清除锁定、普通设置修改不会增加检测记录。超过上限时删除最旧历史，当前持久锁定另行保存，不会因历史滚动而失去清除入口。

记录包含时间、供应商名称/ID、模型、推理强度、来源、相对分数和说明。完成评分的轮次还保存三个样本的有效数字、数量、前三候选、目标模型分、汇总分及异常标记；最多保留两轮，严格检查结构和数字范围。不存探针原始回答、项目正文或密钥；未完成一轮评分时不保存该轮的部分原文。

页面可展开数字证据并导出本机 JSON，以相同样本复算。导出采用字段白名单，排除供应商名称/ID、路由及认证信息，但仍包含你选择的模型和检测时间。内部重试不会增加历史行；最终失败仍保留此前已完成轮次的强差异证据。

存储位置为 `.runtime/model-guard.json`，写入前会保留 `.previous` 备份；不要公开该目录。旧版本迁移只能保留当时仍存在的最终记录，不能恢复已覆盖数据。旧记录缺少逐样本证据时明确标注旧版；重启不将历史通过重新当作有效缓存。

## 无法保证的事情

- 参考库未收录的模型不能据此验证，真实模型版本或采样环境改变也会影响结果。
- 同名模型在不同地区、量化方式、提示词或代理实现下可能出现差异。
- 探针和项目请求可能走不同后端，供应商也可能识别探针或伪造模型名。
- 缓存有效期间仍可能更换模型；缩短间隔只能增加检查频率，不能消除此风险。
- 统计结果可能误报或漏报，不能证明供应商的意图或模型实际推理质量。
- 当前不支持 WebSocket、`/responses/compact` 或不可恢复的加密压缩历史。

因此，本功能适合用作**有成本、有局限的额外检查**。项目仍应通过版本控制、代码审查和测试确认修改质量。需要停用时关闭对应供应商的「模型保护」即可，历史过滤设置独立保留。
